- Dark Indigo #23003F

CASE STUDY STRUCTURE

Every Case Study must use the following structure.

1. CASE STUDY NAVIGATION

At the top:

← BACK TO WORK

Project category:

UX/UI · PRODUCT DESIGN

Project number:

01 / 02 / 03 / 04

Keep the main navigation consistent with the portfolio.

2. PROJECT HERO

Create a large editorial hero.

Show:

PROJECT NUMBER

PROJECT TITLE

PROJECT CATEGORY

Short project introduction

Large visual/mockup area

The project title should be very large and visually dominant.

The visual/mockup area should be the main visual element of the Hero.

Create a responsive image container ready for the real project images.

Do not generate fake product screenshots containing invented information.

Use a clean visual placeholder if real project images are not yet available.

3. PROJECT OVERVIEW

Create a concise project overview using an editorial layout.

Include these fields:

ROLE

TEAM

TIMELINE

TOOLS

PROJECT TYPE

Do not invent information.

If information is not available, create an editable placeholder such as:

[ADD ROLE]

[ADD TEAM]

[ADD TIMELINE]

[ADD TOOLS]

4. CONTEXT

Create a section titled:

CONTEXT

Include an editable content area explaining what the project is and why it exists.

Do not invent facts.

Use placeholder copy where real project information has not yet been provided.

5. PROBLEM

Create a strong editorial section titled:

THE PROBLEM

Provide a large text area for the actual problem statement.

Use an editable placeholder:

[ADD PROBLEM STATEMENT]

Make this section visually impactful.

6. RESEARCH

Create a section titled:

RESEARCH

Create flexible content blocks for research methods.

Possible blocks:

USER INTERVIEWS
SURVEYS
DESK RESEARCH
COMPETITIVE ANALYSIS
USABILITY TESTING
USER OBSERVATION

Do not automatically claim that these methods were used.

Only show methods that are later confirmed.

For now, create editable placeholders.

7. INSIGHTS

Create a section titled:

KEY INSIGHTS

Create 3–5 editorial insight blocks.

Each block should contain:

01
[ADD INSIGHT]

02
[ADD INSIGHT]

03
[ADD INSIGHT]

Do not invent research findings.

8. INFORMATION ARCHITECTURE / USER FLOW

Create a large visual section for:

INFORMATION ARCHITECTURE

and/or:

USER FLOW

Create a large responsive visual container where diagrams, flows or Figma exports can later be inserted.

Do not generate fake UX research diagrams.

9. WIREFRAMES

Create a section titled:

WIREFRAMES

Use a large visual gallery structure for wireframe images.

Create responsive image placeholders.

Allow multiple images.

10. UI DESIGN

Create a visually dominant section titled:

UI DESIGN

Show large image containers for final UI screens.

Use an editorial gallery instead of small thumbnail cards.

Allow:

- desktop screens
- mobile screens
- responsive screens
- component examples

11. DESIGN SYSTEM

Create a section titled:

DESIGN SYSTEM

Show space for:

COLOR
TYPOGRAPHY
COMPONENTS
BUTTONS
CARDS
UI ELEMENTS

The Design System section should visually connect to the portfolio's existing Design System.

12. PROTOTYPE

Create a section titled:

PROTOTYPE

Create a large responsive area where an interactive prototype, video or prototype recording can later be embedded.

Include a CTA:

VIEW PROTOTYPE →

Do not create a fake prototype.

13. FINAL SOLUTION

Create a strong section titled:

THE FINAL PRODUCT

Show large final product visuals.

This should be one of the most visually important sections of the Case Study.

Use large images and editorial compositions.

14. OUTCOME

Create a section titled:

OUTCOME

Create editable areas for:

RESULTS

IMPACT

WHAT CHANGED

Do not invent metrics, business results or user outcomes.

Use placeholders until real information is provided.

15. LEARNINGS

Create a section titled:

WHAT I LEARNED

Create space for 3–4 concise learning points.

Use editable placeholders.

16. NEXT PROJECT

At the end of every Case Study, create a large navigation section:

NEXT PROJECT →

Show the next project title.

Examples:

MIRA APP →
VENTURE PREDICTOR →

PROJECT BUILDER →

RENDICIONES →

The final section should encourage the user to continue exploring the portfolio.
